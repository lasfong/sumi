### Exact all-or-nothing output contract — incomplete

Three fail-open paths remain:

1. **CCI and ATR accept aliases rather than the pinned output.** The implementation accepts either `CCI_${length}_0.015` or `CCI_${length}`, and either `ATRr_${length}` or `ATR_${length}`. The current authoritative engine explicitly emits `CCI_${length}_0.015`; the pinned ATR evidence is `ATRr_${length}`. A different same-length output can therefore render under the released CCI/ATR label.
2. **Bollinger accepts two formatting contracts** (`2.0` and `2`) rather than one discovered pinned output contract. It must choose the exact columns emitted by this engine for the requested parameters, not a permissive alternate spelling.
3. **MACD and Bollinger render partial results.** If an expected semantic component is absent, the code returns any remaining component(s). R2 explicitly requires missing expected output to produce no rendered series. A MACD response lacking signal/histogram or a Bollinger response lacking one band must fail closed as a whole rather than present a partial released indicator.

The strengthened Product UAT also only verifies that runtime values are finite alongside instance parameter values. It does not compare those values to the authoritative backend response for the requested parameter set, so it cannot prove semantic association independently.

These failures violate PRO-IND-02, PRO-IND-04, and PRO-IND-08.
