`REWORK` — REWORK-01 resolves the shared Volume/Volume SMA pane-chrome misalignment, but PRO-04 is still not approved. Released indicator adapters remain parameter-permissive and can render a different indicator output under the requested indicator label instead of failing closed.

## R1 disposition

### Shared-pane chrome — resolved

`IndicatorPaneChrome` now groups visible non-price instances by physical `paneId`. The new 1440×1000 screenshot shows one Volume/Volume Moving Average chrome group aligned with the histogram and Volume SMA line, followed by a correctly aligned Average True Range pane. The prior ATR/Volume label shift is gone. The focused pane-chrome test also proves two physical sections for the shared volume pane plus ATR.

### Explicit semantic adapters — incomplete

`findSemanticColumn()` replaced the generic `available[0]` selection, but it retains permissive fallback matching such as `c.startsWith('SMA_')`, `c.startsWith('ATRr_')`, and `c.startsWith('VOLUME_SMA_')`. Thus a request for SMA 20 with an API response containing only `SMA_10` renders the SMA 10 values under the label `SMA 20`; analogous failures remain for EMA, RSI, CCI, ATR, Volume SMA, MACD, and Bollinger Bands when parameters differ.

The new tests cover irrelevant columns only. They do not cover a semantically similar but parameter-mismatched column, which is the failure that the fallback permits.

This violates PRO-IND-02, PRO-IND-04, and PRO-IND-08, and contradicts the ExecPlan requirement to map the exact pinned backend output for the requested parameters and fail closed on missing or ambiguous output.
