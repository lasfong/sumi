## Implementation & Quality Audit

1. **Provider Boundary Adapter Architecture (`PRO-PROV-06`)**:
   - `MarketDataProviderAdapter` abstract interface implemented in `backend/app/services/data_providers/base_provider.py`.
   - `SSIProviderAdapter` and `VnstockProviderAdapter` normalize daily OHLCV bars into `ProviderCandleDTO` with UTC+7 timestamps and explicit `adjustment_type` tagging.
   - Core domain services remain vendor-agnostic with zero third-party client imports.
2. **Pre-Commit Diff Preview & Conflict Classification (`PRO-DATA-08`)**:
   - `POST /api/sync/preview` fetches data into ephemeral staging, checks existing candles for duplicates and conflicts via `ImportClassifier`, and returns a content SHA-256 checksum.
   - Stale previews fail closed if external candles are inserted before execution.
   - UI provides cancellation, filter tabs (Tất cả, Nến mới, Trùng lặp, Xung đột, Bị từ chối), and explicit user confirmation button.
3. **Immutable Audit Manifest & Sync History (`PRO-DATA-09`)**:
   - Database tables `sync_runs`, `sync_run_items`, and `sync_run_mutations` tracked via Alembic migration `20260816_0002_data_sync_runs`.
   - Manifests record symbol, date range, provider, duration, record counts, and status under version `SUMI_SYNC_MANIFEST_V1`.
   - Accessible via `GET /api/sync/history` and `GET /api/sync/{id}/manifest`.
4. **Transactional Rollback & State Recovery (`PRO-DATA-10`)**:
   - `POST /api/sync/rollback` removes imported daily candles, deletes or recalculates affected weekly bars via `WeeklyAggregator`, and restores catalog metadata.
   - Rollback protects against out-of-order rollbacks when subsequent sync runs overlap the same symbol.
5. **Automatic Weekly Aggregation**:
   - `WeeklyAggregator.derive_weekly_candles` is triggered immediately upon successful sync execution, maintaining internal 1W derivation authority.
6. **Frontend Sync UX**:
