## Blocking findings

### REWORK-03 — Compatibility importer and scripts still bypass explicit confirmation (P0)

The ExecPlan requires accepted candle changes only after a preview checksum is explicitly accepted in a separate operation, and requires legacy/seed/batch entrypoints to enforce the same safe contract or fail actionably (`docs/exec-plans/PRO_03_DATA_CATALOG_AND_IMPORT_QUALITY.md:42, 84, 89`).

`CafeFImporter.import_data()` previews and then immediately calls `accept_import()` in the same method (`backend/app/services/cafef_importer.py:76-119`). `backend/seed_cafef.py:25-41` and `backend/scripts/import_batch.py:45-62` do the same automatically. Routing through the workflow service adds manifests and conflict quarantine, but it does not supply an independent user/operator confirmation boundary. A caller invoking `import_data()` or either script can still mutate accepted candles without receiving the preview checksum and deliberately confirming it.

Required correction: either disable these compatibility entrypoints with an actionable message, or split them into preview and accept commands and require an explicit confirmation input bound to the exact `run_id` and `content_sha256`. Add regression tests proving invocation without that confirmation cannot mutate accepted Symbol/Candle data.

### REWORK-05 — Focused PRO-03 tests are order-dependent and do not isolate database state (P1)

`backend/app/tests/conftest.py` uses one in-memory SQLite `StaticPool`. The `db_session` fixture is function-scoped and drops all tables after each use, while the API `client` fixture is module-scoped and does not clear its data after each test (`backend/app/tests/conftest.py:23-47`). These fixtures therefore share persistent state with incompatible lifetimes.

Independent reproduction:

```powershell
cd backend
& .\.venv\Scripts\python.exe -m pytest app/tests/test_import_classifier.py app/tests/test_import_api.py app/tests/test_cafef_importer.py app/tests/test_import_workflow.py app/tests/test_weekly_aggregator.py -q
```

Result: `1 failed, 25 passed`. `test_import_data_success` expected the first Symbol to be `FPT` but observed `VNM` left by the preceding API tests. The full suite happens to pass in its default collection order, so the green aggregate gate masks the isolation defect.

Required correction: give each test/fixture a transactionally or physically isolated database with matching fixture lifetimes, then prove both the focused command above and the full backend suite pass regardless of collection order.
