## Findings

### P1 — shared volume pane chrome is attached to the wrong rendered panes

`volume` and `volume_sma` correctly share the physical `volume` pane, but `IndicatorPaneChrome` creates one flex section for every non-price instance instead of one section for every physical pane. The two sections for the shared `volume` pane add an extra visual row, shifting subsequent labels relative to the chart panes.

The retained 1440×1000 screenshot proves the defect: the section headed **Average True Range** overlays the raw-volume histogram and the orange **Volume SMA 20** line, while the section headed **Volume Moving Average** overlays the purple **ATR 14** line. The user therefore receives a false value-to-indicator association.

This violates PRO-IND-04, PRO-IND-05, and PRO-IND-11. The new UAT assertion checks chart-series presence but not the visual/chrome-to-pane correspondence; its deduplicated native-pane expectation cannot detect this DOM overlay mismatch.

### P1 — released single-series adapters still accept arbitrary response columns

After special-casing MACD and Bollinger Bands, `IndicatorRenderRegistry.mapBackendData()` assigns `const column = available[0]` to RSI, CCI, EMA, SMA, ATR, and Volume SMA. Thus any response that contains a non-semantic column before the expected indicator column is rendered as an authoritative released series under the wrong label. The new SMA/ATR/Volume SMA tests provide only their correct column and do not prove exact selection.

This directly contradicts the PRO-04 target design: resolve backend response columns in definition-specific adapters and **do not match arbitrary first-column data**. It violates PRO-IND-02, PRO-IND-04, and PRO-IND-08. The current endpoint usually returns only requested output columns, but client mapping must remain explicit and fail closed; ambient column order is not a product contract.

## Required correction — REWORK-01

1. Replace the generic first-column path with an exhaustive released-definition catalog/adapter that selects only the exact pinned backend semantic columns for every released definition. At minimum, SMA, ATR, and Volume SMA must reject irrelevant preceding columns and map their known outputs; Bollinger Bands must continue to choose upper/middle/lower by semantic output. Unsupported, missing, or ambiguous output must fail closed rather than render a mislabeled series.
2. Refactor indicator pane chrome to group visible non-price instances by physical `paneId`. The shared `volume` pane must have exactly one pane container with accurate Volume and Volume SMA controls/values; its placement must remain aligned with the native chart pane, and subsequent ATR/oscillator chrome must not be shifted.
3. Add focused regression tests for mixed/irrelevant column order, the exact semantic mapping of each PRO-04 output, one physical volume-pane chrome group containing both raw Volume and Volume SMA, and pane ordering/alignment after add, hide, remove, reload, replay navigation, and remount.
4. Strengthen the deterministic UAT. It must assert semantic values/series for all four released definitions and assert that native pane order and visible chrome pane order agree, with one volume group containing both raw Volume and Volume SMA. Do not weaken or merely deduplicate an assertion to conceal a visual mismatch.
5. Rerun the focused backend/frontend tests, `scripts/verify-v2.ps1`, `scripts/run-product-uat.ps1`, and `scripts/verify-product.sh` when available through the repository's Windows-compatible invocation. Retain new 1440×1000 and 1280×800 screenshots that visibly show correctly aligned volume/ATR panes; reprove the production DB hash is unchanged.
