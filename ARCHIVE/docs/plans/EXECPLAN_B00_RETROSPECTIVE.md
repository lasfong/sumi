# B00 — Retrospective ExecPlan: Absolute Database Path Anchoring & CWD Guard

## Outcome
Developers, CLI commands, test runners, and backend services can run from any working directory (repository root, `/tmp`, or arbitrary parent directories) without creating rogue 0-byte SQLite database files or drifting away from the authoritative `backend/sumi.db` database.

## Context and problem
- **Review Finding**: GAP-DB-01 (Relative SQLite path ambiguity and ghost database generation).
- **Architecture Decision**: ADR-TX-001 §Decision (Absolute database path anchoring + startup assert + clean ghost database).
- **Acceptance IDs**: GAP-DB-01, DB-ISOLATION-01..05.
- **Problem Statement**:
  Previously, `Settings.DATABASE_URL` in `backend/app/config.py` defaulted to `"sqlite:///./sumi.db"`. When CLI tools, migrations, or Python scripts were invoked from the repository root (e.g. `python backend/app/...` or `pytest`), SQLite interpreted `./sumi.db` relative to the current working directory (`os.getcwd()`). This created an unintended 0-byte ghost `sumi.db` at the repository root, caused migration drift when Alembic was executed from differing directories, and introduced risk of data fragmentation.

## In scope
- Anchor `DEFAULT_DATABASE_URL` in `backend/app/config.py` to an absolute filesystem path pointing to `backend/sumi.db` using `Path(__file__)`.
- Implement `verify_database_path_security(database_url)` to enforce fail-closed validation against unanchored relative SQLite paths.
- Add Pydantic field validator `normalize_database_url` on `Settings.DATABASE_URL` to automatically resolve any relative SQLite path against `backend/`.
- Add lifespan startup assertion in `backend/app/main.py` verifying database path security before accepting traffic.
- Align `backend/alembic/env.py` with `verify_database_path_security` to ensure migration runner parity.
- Safely remove root ghost `sumi.db` after preserving audit evidence.
- Author comprehensive CWD isolation test suite `backend/tests/test_cwd_database_isolation.py`.

## Out of scope
- Database schema modifications or Alembic migration scripts.
- Transaction handling or foreign key enforcement (addressed in B01).
- Provider adapters, quarantine data, or ingest workflow modifications (addressed in B02).
- Frontend application code.

## Invariants
- **Database Safety**: Never mutate, touch, lock, or modify `backend/sumi.db` (SHA-256 hash `ef5c035c27d49de1de51a59e28e1cac5109d92240bcb600239f2180d49128f3e` must remain byte-for-byte identical).
- **Fail-Closed**: Any unanchored relative SQLite database URL must raise `RuntimeError` immediately, preventing rogue file creation.
- **In-Memory Exemption**: Safe in-memory SQLite targets (`:memory:`, `""`) must be allowed without triggering path checks.

## Current architecture
- `backend/app/config.py`: Contained `DATABASE_URL: str = "sqlite:///./sumi.db"`.
- `backend/alembic/env.py`: Inherited `settings.DATABASE_URL` without validating path absolutism.
- `backend/app/main.py`: Initialized engine in lifespan without validating path security.
- Repository root: Contained an empty 0-byte `sumi.db` generated by legacy root invocations.

## Target design
- **Path Anchoring**:
  ```python
  BACKEND_DIR = Path(__file__).resolve().parent.parent
  DEFAULT_SQLITE_PATH = (BACKEND_DIR / "sumi.db").resolve()
  DEFAULT_DATABASE_URL = f"sqlite:///{DEFAULT_SQLITE_PATH.as_posix()}"
  ```
- **Validation Guard**:
  `verify_database_path_security(database_url: str | None = None) -> None`: Parses the URL via SQLAlchemy `make_url()`. If the driver starts with `sqlite` and is neither `:memory:` nor empty, it asserts `Path(url.database).is_absolute()`. If relative, raises `RuntimeError`.
- **Normalization**:
  `normalize_database_url`: Intercepts environment overrides like `DATABASE_URL="sqlite:///./custom.db"` and anchors them against `BACKEND_DIR`.
- **Lifespan Assertion**:
  `app.main.lifespan` invokes `verify_database_path_security(str(engine.url))` at startup.

## Milestones
1. **Milestone 1 — Absolute Path Anchoring & Normalization**: Implement `BACKEND_DIR`, `DEFAULT_DATABASE_URL`, `verify_database_path_security`, and `normalize_database_url` in `backend/app/config.py`. Exit criteria: Unit tests pass for path resolution.
2. **Milestone 2 — Startup & Migration Parity**: Integrate startup check into `backend/app/main.py` lifespan and `backend/alembic/env.py`. Exit criteria: Insecure paths abort startup and migration execution.

## Rollback and compatibility
- **Rollback Strategy**: Revert changes in `backend/app/config.py`, `backend/alembic/env.py`, and `backend/app/main.py`.
- **Compatibility**: 100% backward compatible with existing valid absolute paths and in-memory test databases (`sqlite:///:memory:`). Any tooling previously passing relative paths will now have them safely resolved to `backend/` rather than creating files in random CWDs.

## Risks and mitigations
- **Risk**: In-memory test engines (`sqlite:///:memory:`) might be falsely flagged as relative paths.
  - *Mitigation*: Explicit whitelist in `verify_database_path_security` and `normalize_database_url` checking `url.database in (":memory:", "")`.
- **Risk**: Subprocesses executing in tests might inherit production DB paths.
  - *Mitigation*: Subprocess tests explicitly inject temporary database URLs or inspect `Settings` attributes purely in-memory without calling `connect()`.

## Decision log
- **Decision 1**: Normalize relative environment variables rather than immediately raising an exception.
  - *Rationale*: Allows developers or scripts using `DATABASE_URL="sqlite:///./dev.db"` to have it anchored safely to `backend/dev.db` rather than failing catastrophically, while still raising `RuntimeError` if an raw engine attempts to initialize with an unanchored relative path.
- **Decision 2**: Keep verification function standalone (`verify_database_path_security`) so it can be called from both `main.py` and `alembic/env.py` without importing FastAPI application objects.
